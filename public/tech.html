どうやって投稿を集め、何を保存し、何をしないと決めているかを説明します。

1. 全体の作り

サイトは Cloudflare Workers と D1（SQLite）で動いています。 投稿は前もって集めてこのサイトのデータベースに入れてあり、検索のたびに TikTok へ問い合わせることはありません。

2. 投稿の集め方

  • 過去の分：ログアウトした状態で公開のプロフィール画面を開き、画面が読み込んだ投稿を、作者のブラウザで拾って入れます。確認画面が出たら手で対応し、回避する仕組みは使いません
  • 新しい分：Apify というサービスで、直近の数日分だけを読み、終わった知らせを受けてこのサイトに入れます。失敗や、長く届いていないときは、作者に知らせが届きます

3. 取っているもの・使っているもの

使わないものは、取れても聞きません。

項目使い道画面に出すか
投稿の番号・URL1つの投稿を区別する・埋め込みとリンクリンクと埋め込み
投稿した日時並び・カレンダー・日付で見る出す（日本時間）
アカウント名絞り込み登録した名前で出す
本文検索80文字ほどの抜粋だけ
楽曲の番号・曲名・アーティスト名・オリジナル音源か同じ音源の投稿をまとめる曲名とアーティスト名

動画・画像・音声と、再生数・いいね数・コメント数・フォロワー数は保存しません。

4. 検索のしくみ

本文を、全角半角をそろえて小文字にし、日本語と英数字以外を取り除いてから、2文字ずつに区切って索引（SQLite の FTS5）にします。 検索の語も同じ手順で区切り、続けて現れる投稿を探します。そのため、1文字の語では探せません。 本文が変わっていない投稿は、索引を作り直しません。

5. 投稿の表示

投稿は、TikTok 公式の埋め込みプレーヤー（Embed Player）で出します。 押したときだけ読み込むので、押さないうちは TikTok との通信はありません。

6. 守ること

  • 投稿の本文は書かれたとおりに持ち、全部は表示しない
  • 投稿の本文をAIで処理しない。要約・文章の生成・学習には使わない（プログラムを書くのにはAIを使っています）
  • 検索した言葉やアクセスの記録を取らない
  • 消してほしい・載せないでほしいという連絡があれば、そのとおりに対応する（このサイトについてのフォーム）

7. 構成

  • 画面：HTML・CSS・JavaScript のファイルを、Cloudflare Workers の Static Assets で配信しています。フレームワークと Web フォントは使っていません
  • API：同じ Worker が、/api/posts（投稿の一覧）・/api/calendar（月・日ごとの件数）・/api/accounts（対象のアカウントと件数）・/api/day（その日の投稿）を返します。結果は、Cloudflare のキャッシュに5分置きます。同じIPアドレスから1分に120回を超えて呼ぶと、止めます
  • データ：Cloudflare D1（SQLite）です
